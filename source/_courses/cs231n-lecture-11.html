MY LEARNING RECORD / 11

这一讲，我学过什么？

从 GPU 的计算与带宽出发，学习了训练如何沿批量、序列、层和特征维度拆分。重点理解了数据并行的梯度同步、FSDP 的模型状态分片、激活检查点的重计算，以及流水线中的空闲气泡；也开始用 MFU 区分“设备忙碌”和“有效模型计算”。

01 先核对训练目标全局 batch / 局部均值 / 梯度同步02 显存不只有参数梯度 / 优化器状态 / 激活03 并行仍有依赖和开销通信 / 流水线气泡 / MFU

留给自己的三个提醒

  1. 各卡算得对，还要合并得对。局部 batch 等大时，局部平均梯度再平均等于全局样本均值的梯度；有效样本数不同时，要按实际归一化目标核对权重。
  2. 更多 GPU 不会自动把所有显存合成一个大池子。普通数据并行复制模型状态；分片减少常驻副本，但仍需考虑临时聚合、通信缓冲和激活。激活检查点通过反传时重算部分前向来节省保存量。
  3. 利用率高，不等于训练效率高。数据等待、同步、阶段不均衡和重计算都影响迭代时间。MFU 需要一致口径的有效模型 FLOPs、设备峰值与完整迭代耗时，不能直接用监控面板的 GPU 利用率代替。

训练可以沿哪些方向拆分？

方式拆分对象与我保留的理解
数据并行 DP / FSDP / HSDP不同副本处理不同样本并同步梯度；FSDP 进一步分片参数、梯度和优化器状态，计算时按需聚合。HSDP 在分片组之间再进行复制与同步。
上下文并行 CP沿序列拆分一个长输入。逐 token 运算较直接，注意力仍需组织跨分片的信息交换。
流水线并行 PP沿层拆分，在阶段边界传递激活和梯度。微批让不同阶段同时处理不同工作，减少填充和排空造成的空闲。
张量并行 TP拆分层内矩阵运算，将部分结果拼接或归约。多个维度可以组合使用，但切分方式也决定通信需求。

这一讲让我能更具体地审视双卡训练：先确认全局 batch、梯度累积和同步是否符合预期，再区分数据读取、计算、通信与显存限制。后续比较配置时，需要固定评价口径，记录端到端吞吐和迭代耗时；本页演示不据此推断 DSPFusion 或其他项目的实际加速比。

展开 / 分片与激活检查点解决的是同一个问题吗？

它们都能缓解显存压力，但作用对象不同。分片减少每卡常驻的模型状态副本；激活检查点减少需要长期保留的前向中间结果，代价是反传时重算。真实峰值还取决于分片粒度、预取、临时张量和执行顺序，不能只用参数量估算。

MFU：我希望补进实验记录的一个视角

用“有效模型 FLOPs /（设备总峰值 FLOP/s × 实际迭代秒数）”组织口径。分子不把检查点额外重算当作新的有效模型工作；分母包含实际迭代的等待与开销。这里未采集真实 MFU，也不把下方理想排程比例当作实测结果。
