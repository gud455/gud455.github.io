## 为什么从图像融合读到 MedForge

此前我主要学习红外与可见光融合、扩散模型和退化先验。最近开始把问题延伸到医学图像的可信分析：一张图像看起来合理，是否意味着其中的病灶和证据也可信？模型给出真伪判断以后，能不能说明它关注的位置和依据？

MedForge 是我系统学习视觉语言模型、监督微调和推理强化学习的一篇入口论文。这里记录论文理解、代码核对和我的问题，实验数值均注明来源。

## 先把三个任务区分清楚

| 任务 | 要回答的问题 | 单独需要什么证据 |
| --- | --- | --- |
| 真伪分类 | 图像是否经过篡改？ | 类别标签、分类指标、错误样本 |
| 伪造定位 | 可疑改动发生在哪里？ | 预测框与真实编辑区域的对应 |
| 取证解释 | 哪些视觉现象支持判断？ | 解释中的线索确实存在于图像里 |

医学异常与编辑痕迹是两种不同的信息。真实病灶可能具有不规则边界；病灶被移除的图像也可能没有明显异常。分析时要追问局部纹理、噪声、边界或解剖连续性如何支持“被编辑”的判断，不能仅凭疾病名称推出伪造结论。

1. **图像与问题进入模型。** 图像经视觉编码和特征对齐形成语言模型可利用的视觉表示；文本问题经 tokenizer 编码。训练时的真实框和参考解释属于监督信息，测试输入应按推理协议构造。
2. **模型生成结构化回答。** 先提出可疑区域，再围绕区域描述证据，最后给出判断。真实图像需要相应的无伪造输出约定。
3. **分别检查三个输出。** 分类正确、框覆盖正确、解释可信各自需要评价。仅有结构化文本还不足以验证解释忠实性。

“先定位再分析”是输出组织与训练约束。我把它理解为让解释更容易被检查的一种设计；输出先后本身不能证明文本完整反映了模型内部的决策过程。

## 数据学习：90K 的名称与当前发布统计

论文介绍 MedForge-90K；当前 Hugging Face 数据卡给出的图像统计如下，核对日期为 2026-10-23。

| 当前数据卡类别 | 图像数 |
| --- | ---: |
| Real | 31,990 |
| Edit / 病灶植入或编辑 | 32,394 |
| Remove / 病灶移除 | 30,892 |
| 合计 | 95,276 |

数据覆盖脑 MRI、胸部 X 光与眼底图像。发布材料还包含图像映射、编辑区域、参考解释和训练/测试清单。来源：[官方数据卡](https://huggingface.co/datasets/RichardChenZH/MedForge-90K)。

名称中的约 90K、当前图像总数和实际训练样本数要分别记录。复现时还需要固定数据版本、清单和原图对应关系，检查同一原图的不同编辑版本是否跨越训练与测试划分。

## 训练分工：先学示范，再比较候选回答

**SFT 冷启动**用带有目标输出的样本学习任务、格式和领域表达。**Forgery-aware GSPO**为同一个输入生成多条候选回答，再利用真伪、格式和位置等奖励信号调整生成概率。LoRA 是参数更新方式，SFT 和 GSPO 是训练目标与过程。

这些概念的公式、数值例子和实现对应放在[训练笔记]({{ '/records/medforge-sft-gspo/' | relative_url }})中。对我而言，当前最需要掌握的是一条样本怎样变成监督信号，以及优化目标究竟在鼓励什么行为。

## 实验阅读：分类高分之后，还要检查什么

下表摘录论文 Table 3 的作者报告，均未在我的设备上独立复测。

| 设置 | Accuracy | F1 | 框 IoU |
| --- | ---: | ---: | ---: |
| Binary Classification | 99.42% | 99.31% | — |
| SFT Cold-Start Only | 98.20% | 98.40% | 0.30 |
| 完整方法 | 99.23% | 98.98% | 0.31 |

来源：[论文 Table 3](https://arxiv.org/html/2603.18577v2#S5.T3)。我从这组结果得到三点阅读提醒：

- SFT 到完整方法的分类提升是 **1.03 个百分点**；定位变化为 0.30→0.31，评价时应保留两种尺度。
- 纯分类设置的准确率更高。解释与定位的价值还应通过相应任务的证据评估。
- 0.31 是框的重叠指标，不能写成“31% 的图像定位正确”，也不能用 99.23% 分类准确率替代定位结论。

论文 Table 2 的解释评价中，完整模型的评委均分为 Qwen3-VL-Plus **90.2%**、Gemini 3 Pro **73.9%**。该评价选择了 100 个所有比较模型均分类正确的域内伪造样本；它反映的是这一筛选条件下的解释评分。两个评委分数的差异也提示我记录评委、提示词、样本和评分维度。[Table 2 与评价设置](https://arxiv.org/html/2603.18577v2#S5.T2)

## 目前最关心的三个局限

**奖励与目标的一致性。** Coverage 只检查真实编辑区域被覆盖多少，过大的框同样可能取得高覆盖率；格式标签出现也不能直接验证证据文字是否真实。具体反例与代码条件见[奖励笔记]({{ '/records/medforge-sft-gspo/' | relative_url }})。

**公开材料能否闭环。** 权重、训练入口和评测脚本需要逐项对应。当前已发现公开评测文件存在缺失函数，定位均值的分母也需进一步明确，见[源码核查]({{ '/records/medforge-code-reading/' | relative_url }})。

**泛化评价的范围。** 后续实验需要检查未见编辑器、压缩缩放、不同模态，以及真实病变图像的误报。域内分类成绩不能代替这些测试。
