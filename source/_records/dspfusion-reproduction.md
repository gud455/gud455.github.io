## 双卡参与需要怎样确认

正式训练前，我先经过单卡 20 iter 和双卡 100 iter DDP 检查。Stage I 的起始配置为 world_size=2、每卡 batch=2、global batch=4，实际观察到两张 RTX 4090 均有训练进程、显存和计算负载。

训练过程中会改变 patch 和 batch 配置，因此不能用某一小段迭代速度直接推算整个训练时长，也不能把两卡利用率不完全相同直接解释为某张卡没有参与。

## 自动关机后的恢复核对

训练曾受到自动关机中断影响。我现在更关注“训练状态从哪里恢复”，而不只是再次启动命令。

| 核对项 | 要避免的问题 |
| --- | --- |
| 权重与训练状态的迭代号 | 加载了模型，却重置优化器或学习率 |
| 续训日志的第一条 iter | 实际重新训练，但误以为接着上次 |
| 两个 rank 的设备与进程 | 只启动单进程，或设备分配错误 |
| 数据清单、patch、batch | 恢复前后协议悄然变化 |
| tmux 与实例运行状态 | 会话还在，但训练进程已经退出 |

这些属于本次复现的工程经验，不能替代最终效果验证。

## 推理完成之后还缺什么

同条件输出接近，只是进入评价的前提。少量图或单样本 MUSIQ / PI 不足以代表 968 对总体表现；TReS 曾因依赖权重下载超时没有完成。

接下来需要对齐当前与官方权重的数据、预处理、输出尺寸和指标脚本，保留逐图分数与失败项。LLVIP 可以作额外推理观察，但不能用它替代论文训练数据并仍声称完全复现原协议。
